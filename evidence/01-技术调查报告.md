### 1.4 调查结论（摘要）

**经技术分析，该应用的开屏广告"跳过"按钮存在故意设计的欺诈性行为：**

> 跳过按钮由视觉层和点击层两层重叠组成。视觉层始终全尺寸显示"跳过 5"文字，但实际能触发跳过的点击层仅覆盖视觉层的 30% 至 60%（比例由配置参数控制，该配置通过 JSON 解析加载）。用户点击按钮的大部分区域时，触碰实际穿透到下方广告层，触发广告跳转而非关闭广告。在首次点击（无论命中何处）后，程序代码自动将点击层恢复到完整覆盖，确保第二次点击必然成功。

**排除"程序缺陷（Bug）"的核心理由：**

- 可点击区域比例由配置参数动态控制（该配置通过 JSON 解析加载，具体来源见 §2.2.2 说明）；
- 程序能精确识别"用户想跳过但点击被穿透"的情形，并上报专门的数据统计事件；
- 程序在首次点击后自动将可点击区域恢复至完整覆盖，时机和方式均由代码定义。

## 二、事实发现

### 2.1 现象描述

经实际测试及代码分析，该应用的开屏广告跳过按钮存在以下异常行为：

| 步骤 | 用户操作         | 实际结果                                                   |
| ---- | ---------------- | ---------------------------------------------------------- |
| 1    | 打开 5EPlay App  | 展示全屏开屏广告，右上角显示"跳过 5"倒计时按钮             |
| 2    | 第一次点击"跳过" | **广告未被关闭，反而跳转到广告落地页**（浏览器或应用商店） |
| 3    | 从落地页返回 App | 广告仍在展示，跳过按钮继续倒计时                           |
| 4    | 第二次点击"跳过" | **广告被正常关闭**，进入应用主界面                         |

该现象具有以下特征：

- 第一次点击触发广告跳转的概率远高于正常跳过（具体概率取决于运行时配置参数）；
- 第二次点击必然能正常跳过；
- 跳过按钮在视觉上始终完整显示，用户无法察觉可点击区域的实际边界。

### 2.2 技术原理

#### 2.2.1 跳过按钮的三层视图结构

该应用的跳过按钮并非单一的按钮控件，而是由三个视图层叠加构成的复合结构。自上而下依次为：

```
┌─────────────────────────────────────────────┐
│  第三层：点击捕获层（TextView）                │
│  ┌─────────────────────────────┐            │
│  │  仅覆盖视觉按钮的 30%~60%    │ ← 实际响应点击
│  │  居中放置，用户肉眼不可见     │            │
│  └─────────────────────────────┘            │
│                                             │
│  第二层：视觉文字层（TextView）               │
│  ┌─────────────────────────────┐            │
│  │  显示 "跳过 5" / "跳过 4"   │ ← 用户能看到的
│  │  覆盖整个按钮区域 (100%)     │   但点击该层无响应 │
│  └─────────────────────────────┘            │
│                                             │
│  第一层：按钮背景层（FrameLayout）             │
│  ┌─────────────────────────────┐            │
│  │  半透明黑色圆角背景           │            │
│  │  颜色值：#88000000          │            │
│  └─────────────────────────────┘            │
└─────────────────────────────────────────────┘
         ↓ 第三层未覆盖的区域，点击穿透到下方
┌─────────────────────────────────────────────┐
│  广告交互层（覆盖全屏）                        │
│  ┌───────────────────────────────────────┐  │
│  │  具体广告平台的广告 View               │  │
│  │  （如穿山甲、广点通、快手等）            │  │
│  │  覆盖全屏，任意位置点击 → 跳转广告落地页 │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

**关键事实：**

- 第二层（视觉文字层）向用户展示了完整的"跳过 5"文字，但该层**没有绑定点击监听器**，用户点击该层无响应。
- 第三层（点击捕获层）是唯一绑定了跳过逻辑的视图，但其宽度和高度被人为缩小至视觉按钮的 30%~60%。
- 第三层未覆盖的剩余区域（40%~70%），点击事件穿透到最下方的广告交互层，触发广告跳转。

#### 2.2.2 可点击区域由配置参数动态控制

点击捕获层（第三层）的尺寸由配置参数 `yc.i` 控制。该参数取值范围为 1 至 100，代表点击捕获层占视觉按钮面积的百分比。

**关于配置来源的说明：** `yc` 类存在静态方法 `a(JSONObject)`，表明该配置对象可从 JSON 数据解析而来。结合广告聚合 SDK 的标准架构（配置由广告服务器下发），以及本地默认值为 100（见 §2.2.3）而代码中存在 `i < 100` 的条件分支，可以合理推断运行时的 `i` 值来自外部配置输入。但需说明：**该 JSON 解析方法的方法体因反编译异常而未能还原，无法直接观察 JSON 键与 `i` 字段的映射关系；本报告亦未包含网络请求层面的直接证据（如抓包数据）。** "由远程服务器动态控制"的结论目前基于间接推理，建议通过实际网络抓包补强此环节的直接证据。

| I34     | `da.b.this.o.l()`                                            | **调用 `xc.l()` 方法**，立即将跳过按钮的可点击区域扩展至完整覆盖（100%） |

**综合判断：**

| 序号 | 代码所证明的事实                                             | 为何不能解释为"程序缺陷"                     |
| ---- | ------------------------------------------------------------ | -------------------------------------------- |
| ①    | 开发者预知可点击区域可能小于 100%（I6 的条件判断）           | 程序缺陷不会预先设置特定的条件判断           |
| ②    | 开发者专门设计了加密标签机制来识别跳过按钮（I9-I10 的标签匹配，配合证据 A 的 H8） | 程序缺陷不需要视图标记和追踪系统             |
| ③    | 开发者精确区分"跳过被规避"和"普通广告点击"两种场景（分别上报事件 13 和 12） | 程序缺陷不需要对失败场景进行分类和统计       |
| ④    | 开发者对"跳过被规避"这一场景进行专门的数据统计上报（I13）    | 程序缺陷不需要数据统计代码                   |
| ⑤    | 开发者在处理完广告点击后立即将跳过按钮"修复"至正常状态（I34） | 程序缺陷不会在触发后自动执行精确的"修复"操作 |

**关于事件 13 的数据含义：**

`gcVar2.a(13)` 中的数字 13 是一个事件代码。在 `gc` 类（数据统计/分析模块，文件：`jy_jadx/sources/cn/jy/ad/code/gc.java`）的方法 `a(int)` 中，该事件代码连同其他上下文信息被记录和上报。在本报告的语境中，事件 13 的触发条件决定了其业务含义为："用户点击了跳过按钮的视觉区域，但因可点击区域被缩小，点击穿透到广告层，规避了跳过操作"。

这意味着该 App 的运营方在**主动收集和量化**跳过按钮被规避的统计数据。规避次数越高，广告落地页的访问量越大，广告收入越多。事件 13 的存在直接证明了该设计的**商业动机**。
